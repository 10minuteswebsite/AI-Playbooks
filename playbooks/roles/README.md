# Role Playbooks

Role playbooks add responsibility-specific checks to the Software Delivery Core. A role is a responsibility, not necessarily a separate person; one person or AI may perform multiple roles while preserving their distinct decisions and evidence.

All role playbooks inherit these repository-wide rules:

- business objective before implementation;
- documentation before consequential change;
- domains and contracts before providers;
- explicit canonical behavior sources and traceable derived artifacts where applicable;
- strict organization/tenant, user, resource, and purpose isolation;
- replaceable adapters, idempotent effects, and explicit events;
- risk-proportional tests and verifiable delivery;
- GitHub as the source of truth.
