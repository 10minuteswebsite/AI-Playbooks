# Security Policy

## Reporting a vulnerability

Do not open a public issue containing vulnerability details, credentials, personal data, or exploit instructions. Use GitHub's private vulnerability reporting for this repository when available, or contact the repository owner through an approved private channel.

Include the affected file/version, impact, reproduction using synthetic data, and any proposed mitigation. Do not access data or systems beyond what is necessary to demonstrate the issue.

## Response

Maintainers will acknowledge, triage, contain, remediate, verify, and communicate according to impact. Exposed credentials must be revoked and rotated. Material fixes require regression evidence and review of related playbooks, templates, and controls.

## Scope

Security issues include instructions that could cause secret exposure, cross-tenant data access, unsafe autonomous action, bypassed approval, insecure supply chain, false verification claims, or destructive behavior.
